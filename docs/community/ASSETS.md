# Submitting art

Houses, furniture, zombies, pets, vehicles and animations. Use the **Asset submission** issue form; this page says
what the submission must contain and what happens to it.

## 1. What can be added today

| Kind | Route today | Not built yet |
|---|---|---|
| House-brand skins (logo + colours on an existing object) | [Creator Kit](../contributors/CREATOR_KIT.md): build, verify and gate a pack locally | Signing and publishing packs |
| Furniture and props, houses, zombies, pets, vehicles, animations | Source files plus GLB through the **Asset submission** form; art review; a maintainer integrates it into `tools/blender/` or `public/assets/` | Installable object/body/creature packs (W-084); Asset Bank intake (W-040) |

Nothing reaches the game without art review and the gates in §3. A green automated check is not admission.

## 2. Style

Read [ART_DIRECTION.md](../ART_DIRECTION.md) first. In short, it is a **cosy macabre diorama**: toy-like, bevelled,
chunky, slightly crooked, funny-gross rather than scary, and readable from the game's zoomed-out camera. The game is
rated **E10+**: no gore beyond cartoon stitches and loose limbs, and nothing menacing toward the player.

## 3. Technical requirements

| Requirement | Rule | Checked by |
|---|---|---|
| Format | glTF binary (`.glb`), metres, Y up, origin at floor centre, facing +Z | review + `tests/unit/models/` |
| Triangle budget | Furniture 300–3,000; large items ≤ 6,000; a character ≤ 14,000 with all variants | `tests/unit/models/` |
| Materials | Flat colours, no image textures. The recolourable material is named exactly `Paint`, glass `Glass` | review + `tests/unit/models/` |
| Geometry | No duplicate or zero-area faces, no stray fragments, closed where it should be | review (the Spark lessons: format validators miss these) |
| Footprint | States its grid footprint (tiles) and height; fits it with no overhang into neighbouring tiles | review + `npm run clip:gate` for seats/beds |
| Interaction | Seats, beds and counters: no zombie clips through it in any animation | `npm run clip:gate` |
| Hashes | Every committed file is listed with its SHA-256 in `public/assets/manifest.*.json` | `npm run verify:assets` |
| Rebuildable | Prefer a Blender script in `tools/blender/` that regenerates the GLB byte-for-byte | `tests/unit/models/pipeline.test.ts` |

## 4. Provenance and credit

Every submission states, per file:

- **Who made it** and under which name to credit them.
- **How it was made**: by hand, by script, or with an AI generator. For AI output, name the tool and model and
  include the prompt and every reference image.
- **Rights**: your own work, or CC0. CC-BY only with the exact credit text. Nothing else.
- **No copying**: nothing taken from other games, films or shows; no lookalikes of other franchises' characters,
  logos, UI or trade dress ([IP_NOTES](../IP_NOTES.md) §2); no real brands or logos.

[IP_NOTES](../IP_NOTES.md) §1 currently says every model is procedurally generated by our own scripts. **Before the
first outside asset merges, that section and a contributor credits file must be updated** (community gate G7). Until
then, outside art is accepted only as reference for an in-house script.

## 5. What happens after you submit

1. The form opens an issue labelled `asset` and `needs-triage`.
2. A maintainer checks rights and provenance first. Missing provenance stops the review.
3. Art review against ART_DIRECTION (owner or Claude ZSM).
4. The technical gates in §3 run.
5. Accepted assets merge with credit and ship in the next playtest drop. Rejected ones get a reason on the issue.


## 6. Tools you can use

| Tool | Use it for | Notes |
|---|---|---|
| [Blender](https://www.blender.org/) with the scripts in `tools/blender/` | Models, rigs and animations. This is how nearly all of the game's art is made, and the preferred route: a script can be re-run and reviewed | Free and open source |
| [ComfyUI](https://github.com/Comfy-Org/ComfyUI) | Concept images, textures and reference sheets on your own machine | Free and open source (GPL-3.0). Use it as a tool; do not copy its code into this repository. Record the model and the workflow file in your submission (§4): the licence of the **model** you load decides whether its output can be used here |
| Any other image or 3D generator | Concepts and first drafts | Allowed only if its terms let you release the output under this project's licence. Say which service and model in the submission |

AI-made art is welcome under the same rule as AI-written code: you are responsible for it, and its origin must be
written down.
